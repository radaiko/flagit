API

Two HTTP surfaces on two ports. The public API on :8080 is what your apps call, authorised by a per-device ownership token. The internal API on :3000 is what Hermes and the admin dashboard call, authorised by the admin key — it must not be exposed to the internet.

Conventions

Every response is JSON. Successes are wrapped in an envelope; failures carry a single error string. Timestamps are RFC 3339 in UTC. Request bodies are capped at 4 MiB, and unknown fields are rejected rather than silently dropped, so a typo in a key is reported instead of ignored. 

// success
{ "data": { "id": "FLG-7X3K9Q", "status": "open" }, "message": "ticket created" }

// failure
{ "error": "invalid device token for this ticket" }

Listing endpoints take limit and offset. limit defaults to 100 and is capped at 1000; the response reports the limit that was actually applied along with hasMore.

Authentication

Surface Header What it is
Public /api/* X-Device-Token A UUID minted by the client on first use. The server stores only its SHA-256 hash. Whoever holds the token owns the tickets filed with it; there is no recovery.
Internal /internal/* X-Admin-Key or Authorization: Bearer … Generated and printed once on first start unless FLAGIT_ADMIN_KEY is set. Only its hash is stored, and it is compared in constant time.
Tokens go in headers, never in the URL. A credential in a query string ends up in access logs, browser history and the Referer of any outbound link. The overlay accepts ?token= once from a host app on load, then strips it from the address bar and sends it as a header from then on.

Public API — port 8080

Served with permissive CORS (Access-Control-Allow-Origin: *), because every endpoint is authorised by an unguessable token and no cookies are involved.

Endpoint Auth Description
GET /healthz none Liveness. Returns {"status":"ok"}. Used by the container check.
POST /api/tickets token in body or header Create a ticket. The only endpoint reachable without a header credential, because this is the call that establishes ownership. Rate limited to 10 requests per minute per client.
GET /api/tickets/{id} X-Device-Token The ticket with its conversation. Logs are not echoed back — the reporter sent them.
GET /api/tickets/{id}/messages X-Device-Token Just the conversation, oldest first.
POST /api/tickets/{id}/messages X-Device-Token Append a reply from the reporter.

Create a ticket

curl -X POST https://flagit.example.com/api/tickets \
  -H 'Content-Type: application/json' \
  -d '{
    "type": "bug",
    "title": "The app closes when I tap save",
    "body": "Tapped save on a new note, the app closed straight away.",
    "deviceToken": "6f1c2f4e-6c2a-4c1e-9b6c-1f0a2d3e4b5c",
    "appName": "notes",
    "appVersion": "1.4.2",
    "os": "iOS 18.2",
    "platform": "ios",
    "deviceModel": "iPhone 15",
    "logs": "panic: nil map\n...",
    "logsDurationMin": 5
  }'

type is bug or feature. title and body are required; everything else is diagnostic metadata and may be empty. The response is 201 with the created ticket, including the ID to show the reporter.

Read and reply

curl https://flagit.example.com/api/tickets/FLG-7X3K9Q \
  -H 'X-Device-Token: 6f1c2f4e-6c2a-4c1e-9b6c-1f0a2d3e4b5c'

curl -X POST https://flagit.example.com/api/tickets/FLG-7X3K9Q/messages \
  -H 'Content-Type: application/json' \
  -H 'X-Device-Token: 6f1c2f4e-6c2a-4c1e-9b6c-1f0a2d3e4b5c' \
  -d '{"body": "It also happens on the edit screen."}'

A ticket belonging to a different device returns 403, never 404 — the distinction is deliberate and tells an honest caller what went wrong.

Internal API — port 3000

Every route below /internal requires the admin key. Only /healthz is open, so a container healthcheck needs no credential. The dashboard SPA itself is served from /internal/admin and authenticates in the browser.

Endpoint Description
GET /internal/poll Tickets created or updated after ?since=, one page at a time. Returns now to pass back as the next since, plus hasMore. An absent since starts from the beginning, so a fresh poller can bootstrap.
GET /internal/tickets List tickets. Filters: app, status, type. Paging: limit, offset. Returns total alongside the page.
GET /internal/tickets/{id} One ticket with its conversation, its commits and its raw diagnostics.
PATCH /internal/tickets/{id} Change status, set shippedVersion, add a comment, or all three. Status and comment are written in one transaction. Send "force": true to skip workflow validation.
POST /internal/tickets/batch Apply one status to many tickets — the release sweep. Returns updated and a failed map of ID to reason code (not_found, invalid_transition).
GET /internal/tickets/{id}/messages The conversation, without an ownership check.
POST /internal/tickets/{id}/messages Post a reply as the agent. Visible to the reporter immediately.
GET /internal/tickets/{id}/commits Commits recorded against the ticket. Never exposed publicly.
POST /internal/tickets/{id}/commits Record a commit: commitHash, branch, message.
GET /internal/apps Every app Flagit has seen, with its auto-process setting.
PATCH /internal/apps/{name} Set autoProcessEnabled for one app.
GET /internal/settings Global configuration: globalAutoProcess, hermesWebhookUrl.
PATCH /internal/settings Patch the global configuration. Omitted fields are left unchanged.

Polling

curl "http://127.0.0.1:3000/internal/poll?since=2026-07-27T09:00:00Z&limit=50" \
  -H 'X-Admin-Key: '"$FLAGIT_ADMIN_KEY"

{
  "data": {
    "tickets": [ … ],
    "since": "2026-07-27T09:00:00Z",
    "now":   "2026-07-27T09:05:12Z",
    "count": 3,
    "limit": 50,
    "hasMore": false
  }
}

now is captured before the query runs, so a ticket written mid-query is picked up by the next poll rather than skipped. When hasMore is true, come straight back instead of waiting for the next tick.

Moving a ticket

curl -X PATCH http://127.0.0.1:3000/internal/tickets/FLG-7X3K9Q \
  -H 'Content-Type: application/json' \
  -H 'X-Admin-Key: '"$FLAGIT_ADMIN_KEY" \
  -d '{"status": "resolved", "comment": "Fixed the nil map on save."}'

# The release sweep: many tickets, one version.
curl -X POST http://127.0.0.1:3000/internal/tickets/batch \
  -H 'Content-Type: application/json' \
  -H 'X-Admin-Key: '"$FLAGIT_ADMIN_KEY" \
  -d '{
    "ticketIds": ["FLG-7X3K9Q", "FLG-2M8QT4"],
    "status": "shipped",
    "shippedVersion": "1.5.0",
    "force": true
  }'

Hermes webhook

When a ticket is created and automatic processing applies, Flagit POSTs this body to the configured webhook URL. Delivery is attempted up to three times with exponential backoff (1s, 2s). A 5xx or a transport failure is retried; a 4xx is treated as final, because resending an identical body cannot change the answer. 408 and 429 are the exceptions — both invite the caller back. 

POST <hermesWebhookUrl>
Content-Type: application/json
User-Agent: flagit-webhook/1

{
  "event": "ticket.created",
  "ticketId": "FLG-7X3K9Q",
  "type": "bug",
  "title": "The app closes when I tap save",
  "body": "Tapped save on a new note, the app closed straight away.",
  "status": "open",
  "appName": "notes",
  "appVersion": "1.4.2",
  "os": "iOS 18.2",
  "platform": "ios",
  "deviceModel": "iPhone 15",
  "logs": "panic: nil map\n...",
  "logsDurationMin": 5,
  "createdAt": "2026-07-27T09:04:58Z",
  "ticketUrl": "https://flagit.example.com/api/tickets/FLG-7X3K9Q"
}

ticketUrl appears only when FLAGIT_PUBLIC_URL is set. A missed delivery is never a lost ticket: /internal/poll covers the gap.

Models

Ticket

Field Type Notes
id string FLG- plus 6 base62 characters, e.g. FLG-7X3K9Q.
type string bug · feature
title, body string What the reporter wrote.
status string open · in-progress · resolved · shipped · closed
appName, appVersion, os, platform, deviceModel string Diagnostics from the host app. May be empty.
logs, logsDurationMin string, int Ring-buffer logs and how many minutes they cover. Omitted from public responses.
shippedVersion string Set when a ticket moves to shipped. Shown to the reporter.
createdAt, updatedAt string RFC 3339, UTC.

The device token hash is never serialised. Message carries id, ticketId, body, role (user or agent) and createdAt. CommitInfo carries commitHash, branch, message and createdAt.

Status transitions

From May move to
open in-progress, resolved, closed
in-progress open, resolved, closed
resolved in-progress, shipped, closed
shipped resolved, closed
closed open, in-progress

Re-saving a ticket in the status it already holds is always allowed. Anything else needs "force": true.

Errors

Status When
400 Malformed JSON, an unknown field, a missing required field, an invalid status or type, or a bad query parameter.
401 Missing device token, or an invalid/absent admin key.
403 The ticket exists but belongs to another device.
404 No such ticket, app, or endpoint. Always JSON, never HTML.
405 Wrong method for a known path.
429 Ticket creation rate limit exceeded — 10 per minute per client.
500 Unhandled server error. The message is generic; details go to the log only.
503 The admin key is not configured, so the internal API fails closed.
